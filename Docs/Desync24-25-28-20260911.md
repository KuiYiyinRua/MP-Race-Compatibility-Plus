# Desync 24、25、28：远行队名单与仪式工作分歧

2026-09-11。本轮完成源码候选、编译、22 项离线边界回归及实际安装程序集的 IL/接口核验。**尚未进行游戏内双端测试，没有覆盖正式 DLL，也没有发布工坊。**

## 结论与置信度

- **已证实（24、25 的首处分歧）**：客户端在远行队重组的 `CaravanMaker.MakeCaravan → Caravan.AddPawn → Pawn.DeSpawn` 链多出一次脱离地图操作。此处 Rand 状态相同，不能归因于随机数偏移。轨迹没有记录该次脱离地图的 Pawn ID，不能仅靠这些文件判断是名单不同还是该 Pawn 更早的 Spawned 状态不同。
- **已证实（源码漏洞）**：RW 1.6 的 `Dialog_FormCaravan.Notify_TransferablesChanged` 会根据机械师的选择自动修改 Escort 机械体的 `CountToTransfer`。MP 的 `CaravanFormingProxy` 和 session 共用 transferables；`OpenWindow` 只在发起端执行，之后的界面刷新也只在本地执行。该修改不在 MP 的逐行数量字段 Watch 范围内，而原来的出发路径直接读取 session 名单。它能导致一端多带机械体，是 24、25 的可靠修补方向；**尚未证明额外脱离地图的就是 Escort 机械体，因此不称两份日志根因已经闭环**。
- **已证实（28 的首处分歧）**：客户端的 `Kiiro_Race99587` 在仪式期间先结束工作，进入 `JobGiver_Idle.TryGiveJob`，再由 Pick Up And Haul 的 `IdleJoy_Postfix → PawnUnloadChecker.CheckIfPawnShouldUnloadInventory` 创建卸货工作。主机没有这两条 Job ID 分配。客户端随后火焰调用的栈、Hash、Rand 都和主机对应调用一致。**火焰、冒烟、AM 后续随机消费者不是这里已证实的原因**。
- **未解决（28 上游）**：为何该 Pawn 在客户端先完成当前工作。JIT 窗口显示 `JobDriver_Goto` 的仪式到达标签、`LordJob_Ritual.AddTagForPawn`、仪式阶段切换和 AcceptRole 相关入口，但 JIT 只是首次编译/可达性证据。缺少双方分歧前的 job/toil、位置/路径、角色分配、仪式阶段快照，不能直接归罪于 Pick Up And Haul 或给工作/随机调用加屏蔽。

## 补丁边界

文件：`Source/MP_MeowOnlineShop/Patch_CaravanEscortSelectionMp.cs`，已加入主项目编译清单和启动注册。

1. 只改原版 `Notify_TransferablesChanged` 内唯一的 Biotech Escort 分支开关。对 MP proxy 的普通刷新禁用该分支；单人、非 proxy、未启用 Biotech 的原有行为保留。原来的两处 ForceToDestination 增减逻辑保持原样。
2. 在共享 session 的 AddItems、Notify_CountChanged、Reset 后，以 session 派系创建临时执行用 dialog，执行原来的刷新规则。沿用 MP `FactionContext.Push/Pop`，异常时恢复。
3. 在重组、正常出发、开发者即时出发三个实际执行边界重新计算，时点早于 GetPawnsFromTransferables，可重新归一旧 session 中已被 UI 改过的 Escort 数量。
4. 共享刷新权限限定到当前 dialog 实例，嵌套调用保存/恢复父实例；不会因为一个同步刷新而允许另一个本地 proxy 改动名单。
5. 不额外注册同步命令，不同步窗口，不改 Pawn ID、Rand、工作时钟或火焰逻辑。参数、地图和执行顺序仍由 MP 原有 session/字段同步负责。

入口盘点：初次打开、重复打开、uiDirty 刷新是本地展示；逐行数量变更已有 MP Watch/PostApply；Reset 是原有同步方法；三个出发方法已有原生同步，仅增加执行前规则归一；Cancel 不产生远行队；选择路线/自动补给沿用现有实现，不把它们猜作本次额外 Pawn 的来源。不是所有远行队模组路径都已在本轮穷举。
