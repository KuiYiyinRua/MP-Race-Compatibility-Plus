# RJW 系列联机兼容深度与架构总结

整理日期：2026-09-06  
项目：MP-meow-online-shop  
范围：根据当前项目源码和已有审计文档，总结兼容深度、实现架构及证据边界。

本文不包含新增补丁、修复方案或测试计划。本次整理未编译、部署或启动游戏；历史测试记录不代表当前版本重新验收通过。

## 1. 总体结论

当前项目对 RJW 系列形成了以原生同步为基础、针对缺口补充命令同步，并深入处理确定性与序列化的兼容体系。

兼容已经覆盖 UI 动作、内部随机、集合遍历顺序、本地缓存、序列化和部分组件冲突。各模块覆盖深度不均匀，不能概括为“整个 RJW 系列已全面验证兼容”。

当前成熟度可表述为：**核心覆盖较深，扩展按风险路径覆盖，基础确定性防护较完整，整套载荷的验证完整度仍需单独判断。**

## 2. 兼容深度

### 2.1 RJW 核心：动作执行与内部确定性

核心补丁保留 RJW 自带的同步注册，在未覆盖的位置补充适配：

- 同步深度交谈、右键性行为、自慰及束缚装备工作指令。
- 避免直接传输临时交互对象 `SexInteractionResolved`，改传 Pawn、目标及 Def，在同步执行时重建交互状态。
- 束缚装备指令传输父级 Thing，执行时重新取得组件，避免直接序列化不适合传输的组件实例。
- 为怀孕生成中的 `System.Random` 提供确定性种子。
- 对自主目标选择涉及的 HashSet、Dictionary 候选按稳定 Thing ID 排序，再进行随机选择。
- 在早期类型枚举阶段处理无法正常加载的程序集，降低第三方程序集异常导致 RJW 吸引力系统初始化失败的风险。

这部分已深入核心动作与生成逻辑，但不能由此推断所有自主行为和全部生殖流程均完成运行时验证。

主要实现：`Source/MP_MeowOnlineShop/Patch_RimJobWorld.cs`。

### 2.2 主要玩法扩展：按具体状态变更覆盖

- **Cumpilation、RJW Genes**：处理非确定性随机；Cumpilation 另有组件开关同步。
- **Sexperience**：处理人物生成及相关技能生成路径的随机状态。
- **Onahole 家具**：同步挤奶模式、乳房电极模式及生殖器电极模式选择。
- **SexSlaveCraft**：同步人格凝胶分配，以及训练身份、模式、行为和训练者设置。
- **月经系统**：稳定信息素影响对象的遍历顺序；资源扩展处理杂交资源和子代选择的集合顺序。
- **色情事件**：稳定相关事件对象和群体互动对象的选择顺序。
- **妓院殖民地**：稳定客户候选顺序。
- **色情商人**：稳定可阅读杂志的候选顺序。
- **浪漫扩展**：处理婚礼逻辑中的随机数构造。

这些结论限定于已实现的执行路径。例如色情商人的专项文件处理阅读物选择，不能据此推断其所有交易业务均已专项覆盖；月经补丁也不能等同于整个周期与生殖系统被重写或完整验收。

相关实现文件位于 `Source/MP_MeowOnlineShop/`：

- `Patch_RjwSexSlaveCraft.cs`

- `Patch_RjwEventsDeterminism.cs`
- `Patch_RjwBrothelDeterminism.cs`
- `Patch_RjwEroTraderDeterminism.cs`
- `Patch_RjwRomanceRandom.cs`

### 2.3 P1 附属模组：交互入口与隐蔽状态副作用

P1 补丁覆盖的主要路径包括：

- **家庭关系扩展**：生物父母、AI 母亲关系、仆从状态信件及相关开关。信件在各端重建，其选择继续利用 Multiplayer 内置对话同步。
- **小妾项圈**：关系分配与移除，以及自主对象、建筑选择的稳定顺序。
- **边缘巴士**：指定状态同步，并移除 Getter 自动清位造成的本地状态写入。
- **SM 道具与炮机扩展**：补充公共／私密模式执行方法的同步注册；另处理本地调试设置影响行为概率的路径。
- **树精、魔鬼、动物遗传、性解放框架、隐私意识**：分别针对候选顺序或随机来源进行适配。
- **睾丸和卵巢**：多人时跳过激素面板每帧写状态的路径，由确定性 Tick 逻辑应用结果。
- **UAP**：多人时绕过进程本地的生殖器判定缓存，直接查询 RJW 状态。
- **月经资源扩展**：稳定杂交资源与子代选择的候选顺序。

这部分审计已深入“读取、显示、缓存实际上影响模拟状态”的路径，并非仅检查显式按钮。

主要实现：`Source/MP_MeowOnlineShop/Patch_RjwP1.cs`，以及 `Patch_RjwAddons.cs` 中的相关补充。

### 2.4 跨模块防护：显示随机、序列化和组件冲突

项目还处理了跨模块的基础问题：

- **PE 语音随机隔离**：本地音效播放可能因视野或静音状态不同而被跳过，因此其随机调用不能推进共享模拟随机流。
- **RJW、Sized Apparel 序列化随机隔离**：围绕相关 ExposeData 路径，按稳定 Pawn 身份隔离随机，减少不同序列化分支对地图随机流的影响。
- **月经组件 Def 去重**：同一 HediffDef 被多个种族适配重复加入月经组件时，保留一个组件，优先更具体的派生类型，避免相同路径重复序列化与引用解析冲突。

这些措施触及读档、加入游戏及长期运行可能出现的差异，但不等于所有重连与跨机器场景均已验证。

主要实现：

- `Source/MP_MeowOnlineShop/Patch_RjwPeVoiceRandIsolation.cs`
- `Source/MP_MeowOnlineShop/Patch_RjwSerializationRandIsolation.cs`

### 2.5 无需新增专项代码的内容

已有 P1 审计将部分模组归为依赖既有同步、确定性 Tick、Def 或视觉路径的内容；纯资源与 XML 包通常以双方文件和加载配置一致为基础。

“没有新增专项补丁”不等于缺少兼容，也不等于任意组合都安全。其实际表现仍取决于前置模组、加载顺序、配置和内容完整性。

## 3. 兼容架构

### 3.1 组织方式

RJW 兼容代码集中在本项目 DLL 内，采用按模块拆分的 Harmony 适配方式。各模块通过包 ID、已加载程序集或反射类型判断目标是否存在，再安装对应补丁。

注册入口集中在 `Source/MP_MeowOnlineShop/Patch_SellSlingshot.cs`，包含核心、Addons、P1、序列化防护及其他专项模块的调用。早期初始化防护与普通补丁安装处于不同初始化位置。

整体属于兼容补丁集合，尚不是以统一声明描述所有 RJW 模块能力的通用框架；各模块的目标检查、安装与失败处理存在差异。

### 3.2 原生同步与补充同步的分工

Multiplayer 复制命令并在各端确定性重放，不会持续同步全部游戏状态。

项目因此采用以下分工：

1. 普通工作、能力、已覆盖的对话选择和 RJW 原生同步动作继续使用既有同步。
2. 对未覆盖的本地 UI 状态修改，补充同步执行方法或替换菜单回调。
3. 对已经随模拟运行的逻辑，重点修正随机来源、候选顺序及本地状态依赖。
4. 窗口、音效和其他本地表现原则上保留本地执行；若其随机会影响模拟，则隔离随机状态。

### 3.3 命令参数与上下文

同步命令优先传输稳定的游戏引用和值：Pawn、Thing、Def、LocalTargetInfo 以及整数模式等。需要地图上下文的路径使用 `SyncContext.CurrentMap`。

典型动作链为：

```text
玩家操作 UI
    → 捕获未覆盖的状态变更动作
    → 提交稳定参数与必要上下文
    → Multiplayer 排队并在各端重放
    → 重新取得组件或重建临时交互数据
    → 执行原始逻辑或等价状态更新
```

这避免将窗口、闭包中的临时对象图或不稳定组件实例直接作为网络数据传输。

### 3.4 确定性处理

项目主要采用四类措施：

- **随机源确定化**：将时间种子的 `System.Random` 改为由 `Verse.Rand` 提供种子；替换特定模拟路径中的非同步随机来源。
- **集合顺序稳定化**：在随机抽取或有副作用的遍历前，按 Pawn／Thing 等稳定标识排序。
- **随机状态隔离**：将本地表现、序列化等调用的随机限制在独立作用域，避免推进共享随机流。
- **本地状态影响消除**：绕过进程缓存、去除 Getter 写入、跳过 UI 每帧状态写入，并处理本地调试开关对模拟概率的影响。

### 3.5 反射适配与诊断

补丁使用 Prefix、Postfix、Transpiler 和精确反射定位目标。部分编译器生成的方法通过 IL 操作数或结构特征识别，以减少对固定 lambda 序号的依赖。

目标缺失或签名变化时，相关模块通常告警并跳过对应部分；部分补丁还检查替换数量。此类日志表示目标解析或安装状态，不能代替真实动作验证，也不能理解为功能已安全兼容。

## 4. 验证边界与成熟度

当前应区分三个层面：

- **源码实现范围**：本文列出的补丁路径已在当前源码中存在。
- **历史验证记录**：核心审计文档记录过双端、双地图动作验证；P1 文档记载过验证进行中，以及因依赖或版本问题排除的模块。
- **当前整套运行状态**：本次没有重新核验 DLL 与源码一致性，没有执行完整载荷启动、动作、重连或长时间运行验证。

因此，历史测试不能直接证明当前 DLL、当前全部 RJW 组合已通过完整验收。核心已有较深实现，不意味着所有附属包都有同等测试深度。

最初文档中的 **112 个目录是静态初筛范围，不是 112 个全部完成兼容的数量**。依赖缺失、Def 错误、旧版程序集与实际 API 不匹配，也应与同步问题分别判断。
