## 已落实的五项调整

### 1. Nivarian果树：成熟度脱离渲染缓存

138–145八包首差均为主机的 `Nivarian_Plant_MoonBloomTree95548` 进入 `Comp_FruitTree.RandomScatterOffset`，随后实际创建果实；客户端对应位置已经走向其他tick调用。不是单纯果实图标画得不同。

当前DLL的 `Comp_FruitTree.IsMature` 优先读取 `Comp_PlantRenderer.IsMature`。后者是未保存的渲染缓存，`UpdateRenderCache`受主线程检查限制，并且只在生成/每250tick更新；果实生产每60tick读取它。模拟逻辑因此依赖渲染缓存的初始化与刷新历史。

补丁只替换成熟度getter：读取真实 `Plant.Growth`，与原渲染组件配置的 `matureGrowth` 比较；无组件时保留原0.99阈值。果实Slots原本已经序列化，保留其内容、增长、散布、产物及放置逻辑。没有重置果实进度，也没有包围整个果树tick的随机数。

证据等级：**结果实分支差异已证实；模拟读取渲染缓存的缺陷已由源码确认；该缓存与历史果实进度差异的完整因果链仍待实测/双端状态快照。** 旧存档里已经不同的生产进度不会被本补丁自动拉齐。

### 2. Ariandel雷电：隔离视野控制的特效随机

137在同一雷枪对象、同一tick下，主机已进入伤害随机，客户端仍在 `Visual_Lightning_Gold.ThrowLightningGlow` 的随机数。该方法在 `ShouldSpawnMotesAt` 为真时才消耗五次Rand；玩家观看不同地图/视野可直接改变消费量。

补丁在 `ThrowLightningGlow` 的prefix/finalizer成对保存和恢复Rand，异常路径也恢复，保留异常本身。检查了同类的红、金、紫三个实现并全部覆盖。没有包围 `LightingSpear.Impact`，不改变命中、伤害或真实物品生成的模拟随机。

证据等级：**直接轨迹与当前同MVID源码相互支持。** 红/紫为同构缺陷覆盖，不冒称历史137触发了三个颜色。

### 3. 九尾狐渲染触发的缺失肤色：只读、确定性回退

104的上下文索引3963已经出现不同狐对象（hash相同但label不同），3964是客户端额外肤色随机。完整路径：`HediffComp_HealNinetail.CompPostTick → NinetailRenderUtil.BumpFrameWithoutRebuild → EnsureGraphicsInitialized → ChezhouLib/HAR → Pawn_StoryTracker.SkinColorBase`。

原getter在缺失缓存和黑色素基因时，会随机选色并调用 `Pawn_GeneTracker.AddGene`。因此只给九尾狐的绘制函数套Rand保存/恢复还不够：仍会留下只在一端执行的基因添加。

补丁仅处理MP下缺失肤色的情况：保留现有保存颜色/现有黑色素基因；缺失时根据稳定Pawn ID计算只读颜色，保持原版派系黑色素范围或基因选择权重。不写入角色颜色缓存，不添加基因，不动全局Rand。基因列表在安装时预先建立并稳定排序，避免并行绘制线程触及原版懒加载列表或Rand的全局栈。单机保持原getter行为。

明确行为变化：MP下不会再靠读取外观自动为缺失黑色素基因的角色“补一条基因”；正常的生成/编辑基因流程未改。这是消除隐式游戏状态修改所需的边界。

证据等级：**额外随机与带副作用的getter已证实；未从历史包取得双方完整基因快照。**

### 4. Hediff技能：补上底层界面懒加载保护

107索引1382：主机走到RJW工作检查创建Hediff ID，客户端仍在 `Hediff.AllAbilitiesForReading → AbilityUtility.MakeAbility → Ability.Initialize → GetNextAbilityID`。两端技能缓存/角色能力状态或读取历史已经不同。

本地MP仅直接保护外层 `Pawn_AbilityTracker.AllAbilitiesForReading`；现有核心另有mutant缓存保护，不能代替Hediff自身的分配边界。新增保护在MP界面期返回已存在的Hediff能力缓存，或临时空列表；不把临时列表赋回实例。模拟tick/同步命令仍可按原逻辑初始化真实技能和ID。

证据等级：**懒加载分支差异已证实；底层缺乏界面保护已核验；107是否确由此前界面读取触发仍未证实。** 不修改或伪造Ability ID，不吞掉RJW的真实状态变化。

### 5. 精英袭击：明确派系判定并保存真实周期计数器

96客户端由 `CR_Powerup.Tick → RemoveThis → GenerateSilverOnPawn` 创建白银，主机同位置没有该调用。不能仅凭白银断定是随机源故障：是否移除、是否开启掉落、已有精英状态均可能不同。

源码审计确认：移除条件依赖 `Faction.OfPlayer` / `Faction.IsPlayer`；伤口合并和更新周期的计数器没有保存。新增补丁将玩家判断落实到实际player Def；目标派系优先使用Pawn所在地图所有者、Pawn自身玩家派系，以及MP显式执行/计时地图。尚未生成到地图的袭击角色使用共享事件地图，避免错误借用玩家正在观看的地图；无上述上下文时按共享玩家派系loadID选择稳定兜底。

保存 `spawnTimes`、`_currentTickCount`、`woundMergeTickCounter`；旧档默认值与构造器一致。`m_GameTick`是触发读档 `RestoreData` 的重建哨兵，特意保留为瞬态，避免因机械序列化而跳过重建。死亡、倒地、伤口合并、白银生成和原数据恢复路径保留。

证据等级：**源码缺口已确认，96具体由哪项触发仍未定。** 本轮没有新增整个精英袭击设置同步协议；两端设置差异，尤其掉落开关/数量，仍是96的待排项，不能说本项覆盖全部精英玩法。
