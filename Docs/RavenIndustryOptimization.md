# 渡鸦工业流水线联机优化 1.0.0

状态：代码已完成编译及静态检查；按用户要求未启动游戏、未运行游戏或算法测试。吞吐量等价、联机稳定性及 TPS 收益由用户实测确认。

## 开关

打开 模组设置 → `[MP] Meow Online Shop Compat` → **渡鸦工业流水线优化（仅联机）**。

- 默认关闭，独立于 TPS 优化总开关和所有优化预设。
- 主菜单设置“为新游戏启用”；正在游玩的存档设置“启用本存档”。旧存档缺失此字段时固定关闭，不采用客户端本机默认值。
- 单人游戏不执行优化。可以在单人读档阶段为该存档启用，然后主持联机。
- 房间内仅房主可切换，通过 Multiplayer `SetHostOnly` 同步命令应用，客户端跟随；不会立即单边修改模拟状态。
- 选项随游戏组件保存，加入、重连和回放使用快照中的值。
- 关闭时先还原所有已压缩线路的精确整数坐标，再切换回原算法。

## 实现范围

### 生产容量

在一次 `SimulatePackets` 的同步执行范围内复用库存计数及聚合配方需求，避免两轮端口交付重复进行多层列表查询。保留配方原料首次出现顺序、重复原料累加、缺料预留和非配方材料处理。

库存 Add/Remove/RemoveInvalid/DropStacks 发生前立即使对应索引失效；调参 Invalidate 刷新作用域世代。索引对象通过弱引用缓存复用，内容在每个新运输执行范围重新读取，不会长期缓存未知外部库存。执行范围外继续调用原容量计算。

### 调度队列

对 512 桶调度器提前剔除失效修订的远期事件，避免无效记录跨多个桶周期保留。有效事件的时间、原始顺序、回调追加的事件后缀和机器执行逻辑保持原样。

没有改成“只保留最早事件”，没有提前生产，没有删除机器原有唤醒通知，也没有改变自动开工检查的节奏。

### 普通传送带整段推进与堵塞移动休眠

对至少 8 个包、队列连续 4 次推进阶段没有结构变化的普通开口线路建立坐标表示。阈值只选择等价计算路径，不跳过游戏 tick。

原生一次完整推进后，记录每包的基准与夹持上限，以整段累计位移推进。完全压紧且到达端部的线路不再逐包更新位置。原有货物包不合并，类型、数量、排序、分流轮询游标均由原系统维护。

坐标表示的推导（`s` 为间距、`E` 为端点、`x_i` 为原推进后坐标）：

`b_i = min(x_j + j*s, j <= i) - i*s`

`x_i(d) = max(0, min(b_i + d, E - i*s))`

其中 `d` 是后续相同参数下累计的整数位移。负基准保留堆在位置 0 的尾包逐步释放延迟，不能简单给它们统一加坐标。原始整数溢出范围无法排除、参数变化或过渡未完成时退回原方法。

全部 17 个原生 PositionFixed 读写方法经过坐标适配。队列 Add/Insert/RemoveAt/RotateLeft/Sort/Clear/索引赋值前还原；原始字段写入前还原；拓扑变更、地图移除、游戏/地图保存、关闭开关时还原。显示只读取计算后的坐标，不因摄像机位置改变模拟。

对象和索引容量重复使用，避免每次货物进入或离开就分配整条线路的包装对象。频繁变更的队列不会反复建立索引。没有稳定普通线路时保留原 Burst 路径；有稳定普通线路时避免为整段更新复制全部货物到原生数组。

### 保留原行为的边界

- 两轮转移请求的顺序、端口检查相位、15 tick 队首换料仍执行。
- 本版本的堵塞休眠是**停止整段内部的逐包位置计算**，不是取消所有端口探测。未知容量适配器、过滤器和混料规则仍由原系统实时判断；不使用可能漏通知的长期“下游没变”标记。
- 跨线过渡、源线路限位、闭环及不满足条件的短线路保留原处理。仅闭环的负载继续使用原 Burst 选择。
- 液体仍按原 60 tick 周期和浮点分配顺序运行；拓扑仍采用原编号与重建规则。方案中后续可选的液体休眠、局部拓扑重建本次没有启用。
- 不改变普通机器生产周期、配方、功耗、产量、物品包大小或随机数。

## 加载与兼容防护

新模块：`RavenCompatibility/Assemblies/Meow.RavenIndustryOptimization.dll`。利用现有 LoadFolders 的 `ZuoYao.RavenRace` 条件，仅在安装渡鸦时加载；未覆盖渡鸦原 DLL，也未重编译已有 Meow 核心/渡鸦兼容模块。

绑定的原 DLL SHA-256：`74AE9E1DDC75F97B49A2AF08B6F3C0AA73B5F620F2D60F6BF9E65E624AD1834B`。

启动时检查：

- Multiplayer API 可用，目标版本、字段和方法布局匹配。
- 现有 `RavenConveyorPacketState` 在 Map.ExposeData 和 EnsureTopology 上的实际后置补丁已经安装；仅存在该类型不够。关闭渡鸦兼容分类会使本优化不可用。
- 覆盖的关键计算目标没有其他模组提前改写；外部程序集直接访问原货物 PositionFixed 时拒绝启用，防止其读取尚未还原的坐标。
- 初始化失败会撤销本模块的模拟补丁，保留设置页错误说明。自启动后再注入的新补丁或未知反射式直接读取不在当前静态覆盖范围。

正常启动日志：`[Meow.RavenIndustry] READY 1.0.0 MP-only`，并打印目标 DLL 指纹及本模块 MVID。

## 编译及本轮检查

在模组目录执行：

`dotnet build Source/RavenIndustryOptimization/RavenIndustryOptimization.csproj -c Release --nologo`

结果：零警告、零错误。静态元数据工具仅使用 Mono.Cecil 读取 DLL，不加载或执行游戏、Unity、Harmony 或优化算法。检查 29 个目标方法及 17 个坐标访问方法。此检查不等于实际游戏加载、联机稳定性或 TPS 验证。

另有独立静态架构/同步审查，已补上实际存档补丁安装门禁，并核对动态 IL 的字段访问及参数宽度。以上不等于 Harmony 在实际游戏加载成功，不等于运行验收。

## 用户验证建议

所有玩家使用同一 DLL 并重启游戏，先在存档副本中开启。优先观察满带堵塞后恢复、混合原料换料、分流汇流、生产中断电、运输中拆带、带货存读档、非房主加入及重连。开关关闭后也检查运输恢复。

若只测性能，分别看长运输线与频繁进出货的短密集工厂；本版本主要针对前者及堵塞货物移动，没有测得 TPS 增幅。

回退：房主通过开关关闭并保存；如需移除模块，在退出游戏后移除新增的单独 DLL。货物仍以原格式保存，没有新增权威货物存档结构；新增游戏组件只保存开关。
