# 本地补丁 3.0.158：恢复所有地图原生更新

## 原因与修复

旧实验调度器会跳过整段 `Map.MapPostTick`，其中包含 `PowerNetManager.PowerNetsTick`。原版电网的用电器启动检查还受绝对 tick 取模条件限制。两张地图采用不同错峰相位后，第二张地图获准更新的 tick 可以永远错过用电器开机检查；电缆连接正确也不会供电。

在隔离的原版木燃料发电机、电缆、落地灯双端测试 PM02 中，旧核心 3.0.156 重现了 map 0 灯亮、map 1 灯灭。两端输出同样状态，map 1 的电源与灯连接同一电网，因此不是特定模组发电机的问题。

3.0.158 停用整个实验地图节流器，移除它的 `MapPostTick` Harmony 前缀及静态开关缓存。电网、环境和 Fleck 交回原版及 Multiplayer 的地图调度，每个真实地图 tick 正常推进。旧存档字段仍按原格式读写，但不能再次启用这个节流器；设置界面说明其已停用。其他独立优化保留。

证据目录 `BuildValidation/PowerMapFix_20261013` 中：`runtime-summary.json` 汇总实测结果，`Runtime/PM01`–`PM05` 保留原始日志、两端模组列表、输入散列、进程命令行、冻结状态及截图；`deployment.json` 和 `deployed-static-gate.json` 记录部署与门禁。失败的旧版对照明确分开保留，不计入新版通过结果。

测试是本机隔离双端、精简原版电网场景，不等于完整 247 模组现有存档回归，也不等于跨电脑测试。此次修复不处理原日志内 Tina/NSHN 的反复空引用、自动存档临时 ZIP 冲突或其他模组 API 不匹配。

原日志的 7,352 条同引用编号异常中，缇娜占 5,189 次、NSHN 占 2,163 次：同一角色 tick 反复触发空引用，被逐对象捕获后下一 tick 再次重试，最终触及日志消息上限。另有 4 次自动存档临时 ZIP 已存在导致的保存失败。电网故障与这些异常是不同的已观察问题；本次没有确定角色空引用的具体字段，不能把堆栈出现的全部 Harmony 补丁视为原因。完整初始诊断保存在 `BuildValidation/PowerMapDiagnosis_20261013/REPORT.txt`，其“仅分析、未测试”是修复工作开始前的历史状态。

## 使用

所有玩家安装同一更新并完全退出、重启游戏后再联机。原版电网会在恢复地图更新后自行重新结算，无须为了这个补丁重建地图。旧会话不会热加载新 DLL。停用地图节流可能降低此前以跳过模拟换来的 TPS。

这是本地更新，未发布到创意工坊或 GitHub。根目录旧公开版本 manifest 仍为历史发布记录；本次以专属部署记录和更新包散列为准。
