## 源码依据

涅拉来自 workshop 3624805128，包 `keeptpa.NivarianRace`，作者 keeptpa，版本 20260922151508。没有随附源码，公开源码检索未找到能与安装版本对应的仓库，分析使用精确安装 DLL 的反编译。

`Nivarian_Race.dll` SHA-256：`A58F00EBC704AB03163BFF94181B3C6901D2B86F9F500FB0C4D470D7A10CBFF3`。

骰子列表、每日日期、rolled、consumed、选项均有原生存档字段。UI 的 `OnTabSelected` 和 `DrawHoloDice` 会调用 `RefreshHoloDice`；旧补丁禁止 UI 执行刷新，但未发送替代同步请求。原生后台刷新位于每 60000 tick 的评估分支内。投掷本身已注册为世界同步命令。

本地 Multiplayer 源码表明，世界命令不会建立地图命令的 `TimeSnapshot` 或固定 `Find.CurrentMap`。事件筛选、默认事件参数、第三方事件的 `CanFireNow` 因而可能读到不同的地图与时钟。旧版双客户端对照运行 ND03 实际记录到主机投掷时 `current=0`、客户端 `current=1`，两端原生事件目标仍为 home map 0。这证明上下文漏洞存在；该干净存档的骰子结果仍一致，不能声称它完整复现了历史 470/471/475。

最新用户快照（冻结 ZIP SHA `e20e27b808f18b49167561896f240ab4c27d3bb2420ffa71db3aad8f6f97af5c`）包含 247 个 mod、两张地图、一枚未投掷骰子，Nira 等级 2、lastHoloDiceDay 58、lastAssessmentTick 7650811；XML 的 ticksGame 为 3565824。历史时钟留下的评估时间可能长期阻止后台每日刷新。此证据支持补齐 UI 刷新及投掷前刷新，但不能恢复分歧瞬间客户端的每个 guard 值。

钻地货舱使用安装包 `RKU.RatkinUnderground`（3613814532，作者 Anxie）随附的 1.6 C# 源码，并对照安装 DLL，SHA：`140880C0DD5F234D1EEC59C5BB5DB1AD40DD6F2734B4237E3E5A53BB99D45C91`。原生 Tick 的暂停判断包围烟尘分支；MP 的 `TickManager.Paused` 读取当前镜头地图的异步速度。两次浮点随机数仅用于烟尘位置，不决定货物、移动或寿命。

## 补丁边界

- `NivarianDiceContext`：在原生刷新、投掷、使用、跳过执行期间建立世界时钟、玩家地图管理器及原生 home-map 事件查询上下文，最终恢复本地查看状态。投掷前调用原生每日刷新，再执行原生索引和 rolled 判断。
- UI 每日刷新：同一客户端每个世界日最多提交一次世界同步请求；使用原生刷新逻辑，不在绘制时修改共享骰子列表。
- `CargoPodVisuals`：原生 Tick 在 MP 模拟中不再依据镜头地图暂停状态跳过烟尘，两处偏移改为显示随机数。货物交付、投射物、特效计数、寿命逻辑保持原生执行。
- 不把骰子整段 Rand 推入/弹出，不复制主机生成结果，不按现有证据无法证明的原因修改 469/474。

诊断日志受 `-meow-dice-diagnostic` 控制，普通游戏仅输出目标解析摘要。
