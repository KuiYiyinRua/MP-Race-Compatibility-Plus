## Patch and static verification

`AuroraVisualRandom` patches the exact installed `GameCondition_Aurora.GetNewColorIndex(): int` method with a prefix/finalizer `Rand.PushState`/`Rand.PopState` pair, active only in Multiplayer. The source of the installed game method was inspected: it chooses only the next color for `SkyTarget`; the color indices and transition are saved. Multiplayer's local source patches aurora incident targeting/end behavior but has no color-Rand boundary. The patch is registered under the visual category, with a fail-closed signature check and group failure log. DesyncBatch version and startup READY text are 1.0.5.

Release build: zero warnings, zero errors. The archived candidate DLL is `Candidate/Meow.DesyncBatchCompatibility.dll`, SHA-256 `9AE925C6FAB53B4D389CF52F6304550137F54FC78CCAAF865A8EF52C3487DC52`; decompilation confirms the prefix, finalizer and registration. No game test was run per request. The formal `1.6/Assemblies` DLL remains 1.0.3 (`39094C8E9DB3B0445041CE00CA15009BEAC242C6F97BE133CF09A0453FE79396`) because two separate RimWorld processes were running at deployment inspection. This build is compiled and statically inspected, runtime unverified.
