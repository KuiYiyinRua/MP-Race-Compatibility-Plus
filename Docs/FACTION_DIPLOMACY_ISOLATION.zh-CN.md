# 多派系外交与剧本永久敌对隔离

## 行为约定

以玩家 Faction 实例为身份，不以客户端、地图视角或共享的 FactionDef 为身份。同一个 PlayerColony 定义建立的两个派系，各自保有 Milira 的开局限制、和解标志、好感度和自然恢复计时。

- 普通开局保留 Milira 的永久敌对；Milira 开局与 Kiiro categoryTag 开局免除此限制。
- Milira 开局对 Skyfeathered Church 的敌对不传给其他玩家。
- 免除永久敌对不等于永久友好。攻击、赠礼、俘虏与任务造成的正常关系变化继续生效。
- 原模组的和解标志只属于执行玩家；不修改全局派系定义白名单。
- 玩家间关系共用该对关系本身；A-B 应相互一致，不应复制到 A-C 或 B-C。
- 旧档保留已保存的基础好感度。历史敌对没有足够来源信息，不能自动判断是错误初始化还是玩家主动开战，故不自动归零。

## 实现边界

入口位于 Source/FactionDiplomacyIsolation/Diplomacy.cs，编译为独立的 Meow.FactionDiplomacy.dll。原发布核心 DLL 保持字节不变；模块先确保旧核心初始化，再精准撤销其两个旧外交补丁，并禁用旧的1000 tick中立化循环。保留旧 GameComponent 类型以解析旧档。接管数量不符时拒绝启用，安装失败时恢复已撤销的旧补丁。新记录使用 Scribe 深度序列化，派系使用引用序列化。读查询不创建存档状态，新增玩家在同步派系创建路径登记。

永久敌对规则同时覆盖双向查询、原版初始好感度本地函数与 CanChangeGoodwillFor。后者保留 HasGoodwill、已灭亡、自身、攻城和任务锁定条件。好感度读写在明确的 player-NPC 上下文内执行，并在 finalizer 中恢复。

GoodwillSituationManager 的情境查询按当前玩家计算，避免按 NPC 单键缓存串扰；后台 RecalculateAll 按已登记玩家和目标派系稳定排序，直接通知关系重算，避免递归进入旧核心的观察者前缀。自然恢复沿用原版区间（自然值±50）、3000000次计时阈值和最多10点的基础步长，但计时器以玩家/NPC配对保存。原版调整函数仍决定实际增减量。

Milira 三个外交字段的实际读写入口使用匹配安装版本的 Harmony IL 替换接入记录。原版启动和读档中对 Milira/教会 Def 的已知改动在隔离会话中被阻止；从单人档开房时以启动后 XML 定义为基线恢复。单人原始外交标志仅迁给可确定的原玩家，不向旧多派系档所有玩家广播。

当前适配器针对 Milira 本体、Milira 玩家开局和 Kiiro 玩家类别。它不是对所有第三方剧本的通用“全兼容”声明。其他模组若直接改 FactionDef、静态规则或保存全局任务状态，仍需逐个核对并增加适配。

## 剧情范围

本次隔离外交规则，不把 Milira 的全部任务、天使角色、威胁计数和事件队列改成逐玩家副本。原全局剧情组件使用稳定排序后的玩家地图及其所属派系进行外交门禁判断，避免本地 CurrentMap 或观察者派系决定结果。它仍是全局剧情单例。

安装版 Milira.dll 存在交还角色的 WorldObjectCompMiliraSettlement 回调，但其组件没有挂载到本轮安装的据点定义。代码保留该回调的同步和执行前验证，并补齐 SetRelation 遗漏的反向基础好感度；不得据此宣称当前版本实际显示该按钮。测试若直接准备和解状态，必须注明是状态转移夹具。

## 验收要求

1. 同时创建两个相同 PlayerColony 定义的普通派系、Milira 派系与 Kiiro 派系，核对双向基础值、有效值、关系类型及敌对限制。
2. A 和解、B不变；Kiiro主动交战后经过1000 tick以上仍保持合法敌对。
3. 交替查询不同派系与同一NPC，验证好感度上限不串扰；验证不同NPC和玩家间关系不串改。
4. 验证赠礼/负向行为、任务锁、攻城限制和不同配对的自然恢复计时。
5. 非房主触发实际 Faction 创建及好感度变更路径，主客结果一致；合成状态转移不冒充可达界面操作。
6. 存档、重开和冷加入保留记录；不同客户端视角不能写状态或改变随机序列。
7. 约10000共享tick冒烟、120000共享tick持续运行及冷重连；最终发布DLL必须与验证候选哈希一致。

## 迁移与回退

已有档的基础好感度不自动修复，曾被旧补丁抹掉的历史好感度无法逆推恢复。旧共享自然恢复计时无法可靠归属，新配对计时从零开始。从旧多派系档升级时，来源不明的全局和解标志不复制给所有玩家；没有独立和解记录的普通派系采用保守敌对规则，因此有效好感度上限和正常重算后的关系类型可能改变，保留基础数值不等于保留无法归属的旧和解。移除补丁不会撤销已经发生的外交行为；回退需要保存升级前的备份，并使用原版本模组重新打开该备份。不要用旧版本加载新版本保存的数据来假定可逆。

## 验证状态

运行时结论见同版本发布记录。仅编译通过或方法注册成功不构成双端完整验收。
