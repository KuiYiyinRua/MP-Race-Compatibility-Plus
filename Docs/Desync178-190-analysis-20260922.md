## 逐包结论

### 178：飞行射击位置存在本机时间输入，强支持

最后有效 tick 2152321。首处分歧在全局 2152375、索引 3119：同一颗 `Raven_Projectile_BlackGoldRevolver618990` 在主机地图 tick 4293082 进行碰撞随机判定，客户端在 4293083 才进行。其抽取后的 RNG 状态相同；但主机 4293084 又出现一次该弹丸的碰撞抽取，不能只视为交换了两条记录。

主机 JIT 在 2152362 已记录乌鸦商队进入战斗、FlightUtility.TakeOff、Chezhou 飞行起飞。实际 Chezhou 程序集中 `Patch_FlyingDrawPos.Postfix` 使用 `Time.realtimeSinceStartup` 和 `Sin` 修改 `Pawn.DrawPos.z`；原版 `Verb_LaunchProjectile.TryCastShot` 将 `caster.DrawPos` 传入 `Projectile.Launch`，后者据此计算飞行时间与碰撞路线。MP 的确定性保护在更底层的 `PawnTweener.TweenedPos`，后置修改仍会漏入模拟。此路径与日志中的弹丸早晚一个 tick 高度吻合。

### 179：同一颗弹丸提前一地图 tick 命中，强支持同一漏洞

最后有效 2156611，首处分歧 2156651、索引 480。客户端 `Raven_Projectile_BlackGoldRevolver642898` 在地图 4293784 碰撞、销毁并伤害 `Raven_Building_MineralExtractor449039`；主机相同调用链发生于地图 4293785。不是 `SocialInteractionsManager` 的随机算法有问题：它只是主机在此处的下一条记录。使用上面的飞行位置边界修复，不对社交组件加随机隔离。

### 180：黑雾榴弹单端多一次碰撞抽取，强支持同一漏洞

最后有效 2159311，首处分歧 2159345、索引 129。主机 `RavenProj_BlackMistGrenade643308` 额外执行 `CheckForFreeIntercept`，客户端下一步已是另一颗吹箭撞墙。进入分歧之前的抽取一致，此处起相同撞墙代码的 RNG 相差一次抽取。与飞行弹道输入问题一致，但没有存档中的 origin/destination 数值，不能声称已证明每颗弹丸的数值传播。

### 183：野兔路径到达后结束工作，只能定位分歧

最后有效 2225341，首处分歧 2225396、索引 1568。主机 `Hare617247` 经 `PatherArrived → Notify_PatherArrived → EndCurrentJob` 分配额外 Job ID。客户端没有该事件；随后电网的相同抽取仍逐条保持同一 RNG。包内未提供野兔目标、路径进度或工作内容，不能判定是哪项状态先不同。没有修改通用寻路或 Job 结束逻辑。

### 184：空投舱单端先开舱，只能定位分歧

最后有效 2240011，首处分歧 2240065、索引 1609。客户端 `ActiveDropPod661698.PodOpen` 生成 `Milian_UniversalInterfaceUnit661595` 并销毁舱体，主机该窗口没有对应事件。JIT 显示客户端在 2240017 到达任务奖励空投链。

核实原版 `ActiveTransporter.age` 已序列化，`Tick` 按 age 与 contents.openDelay 开舱，不能归因为“age 没保存”。没有两端舱体创建时间/age/openDelay，尚不能归因于 TickList、任务调度或运输状态。恢复涅瓦莲后续补丁安装有独立价值，但不能据此宣称这个原版 ActiveDropPod 已解决。

### 186：客户端在该窗口到达新地点，只能定位分歧

最后有效 2278591，首处分歧 2278625、索引 307。客户端经 `TravellingTransporters.TickInterval → Arrived → VisitSite.Arrived` 分配到达消息 ID，并继续选落点；主机下一条是另一地图电网抽取。客户端 JIT 也记录海岸地图生成。

原有 `Patch_TransportVisitSiteMp` 已将新地点抵达保持在同步调用栈内，实际 trace 也证实如此，故不能重复补“禁止 LongEvent”并声称修复。缺少两端 traveledPct、到达动作、目标地图/任务状态，尚不能确定提前抵达或动作有效性差异的来源。

### 187：九尾角色单端结束当前 toil，只能定位分歧

最后有效 2346811，首处分歧 2346867、索引 1253。客户端 `Ninetailfox108007` 经 `JobDriver.CheckCurrentToilEndOrFail → EndCurrentJob → DetermineNextJob → ThinkNode_PrioritySorter` 进入新的工作选择；主机没有。第一次新增抽取使用的 RNG 与主机下一次电网抽取相同，说明是执行了不同分支，而非此前 RNG 已偏移。缺少当前 job/toil/目标/结束条件，未给 PrioritySorter 增加会掩盖状态差异的随机作用域。

### 188：取消蓝图命令效果单端出现，只能定位分歧

最后有效 2350591，首处分歧 2350636、索引 784。主机 `AsyncTimeComp.ExecuteCmd → HandleDesignator → Designator_Cancel.DesignateThing` 销毁蓝图，随后有邻格随机枚举；客户端同一窗口无此效果。其它地图电网流保持一致。现有 trace 不含命令负载和蓝图对象状态，不能区别目标已缺失、重复动作或更早命令状态分歧；不增加重复同步。

### 189：交易会话在一端重新创建，只能定位分歧

最后有效 2364121，首处分歧 2364179、索引 1392。客户端在已同步的 `CaravanVisitUtility.TradeCommand` 中调用 `MpTradeSession.TryCreate`，新增 session ID 与永久银币 Thing ID；主机没有这两次分配。

核实 MP 的 TryCreate 在 `SessionManager.AddSession` 拒绝冲突时直接返回；成功时才分配永久银币。证据支持“成功创建/已有会话状态不一致”这一类问题，但不能确定是哪端会话为何残留或丢失。现有兼容代码已含 PostLoadInit 保留与精确参与者匹配；无对象转储时，强行删会话或重建会话会破坏正在交易的另一玩家，因此不做此类补丁。

### 190：单端进入 JobDriver 异常恢复，只能定位分歧

最后有效 2379781，首处分歧 2379837、索引 2527。客户端 `Ratkin809151` 经 `JobDriver.DriverTick → JobUtility.TryStartErrorRecoverJob` 分配新 Job ID。主机没有；对齐后电网 RNG 仍相同。该包日志是 178 的旧截断日志，没有此 Ratkin 的异常原文。不能把早先 Cougar 的 Ballz 异常套用到该角色，也不能吞掉 JobDriver 的所有异常。

## 用户补充：Milira Imperium 专属 UI 捐赠

用户确认其中两次由 3588393755 的白银/黄金捐赠触发。当前安装的 MiliraImperium.dll MVID 为 `214e273f-1173-4c78-ba7f-1e01bea1c46b`。反编译确认：`DrawDonationRow → RunDonation → MiliraImperiumTransactionService.TryDonate → TryConsumeResource → TradeUtility.LaunchThingsOfType` 扣款，随后 `Pawn_RoyaltyTracker.GainFavor` 增加荣誉并触发相关副作用。现有 AriandelMiliraImperium_Compat 只注册旧 GameComponent 方法和其他组件操作，未覆盖这个新交易入口；日志补丁清单也没有 RunDonation/TryDonate 同步补丁。

这是明确的界面直接修改模拟状态缺陷。新增 `ImperiumDonation.cs` 在 RunDonation 入口截获联机界面操作，将地图、角色、派系、资源种类、数量作为同步命令参数。原窗口及本机选择只在发送前读取；接收端不依赖 Find.CurrentMap/Find.Selector，也不重建窗口。执行端调用完整原始交易，重新验证联盟、角色 royalty 和可发射资源余额，扣款与荣誉在同一命令内完成。白银、黄金和同页其他捐赠材料共用该路径，单机保留原行为。milira 类别开关和原 Milira_MP 所有权避让仍生效。

35 项新离线检查中有 12 项针对本入口及交易 IL、上下文参数、注册点、真实资源枚举及银/金荣誉比率。未运行游戏。现存 trace/JIT 窗口没有捐赠调用链，累计日志又已截断，故不能可靠确定用户所述两次对应的 ZIP 编号；也不能将 184 的任务空投直接称为捐赠奖励。此根因与修复明确，但逐包归属仍未证实。

## 已修改的五处边界

1. **飞行显示与模拟隔离**：`Source/DesyncBatchCompatibility/FlightSimulationBoundary.cs`。在联机模拟期间跳过 Chezhou 的实时悬浮位置 postfix；界面仍保留飞行动画。原 postfix 还有揭雾副作用，不能只在模拟跳过：将联机揭雾移到真实 CompTick，使用 pawn.Position 和原有已保存高度计算范围，界面不再写 fogGrid。单机仍走原调用。
2. **无名字动物异常**：`LoggedBoundaryFailures.SafeAnimalName` 精确替换 Ballz 的 `pawn.Name.ToStringShort` 调用链，名字为空时使用 LabelShort。日志 Ref A7C09497 及对应程序集 IL 证实它发生在 RemoveHediff 之后、RemoveTesticleGear/后续处理之前。补丁保留完整健康、装备和消息副作用，不吞异常，不把它认作 190 的已证明根因。
3. **旧地图特效引用**：`LoggedBoundaryFailures.LiveEffectMap` 防止 Raven 特效注册器对 components 已清空的旧 Map 调用 GetComponent。日志 Ref EFE63A65 的报错正是该路径，连续刷屏使后续包都只能附带旧日志。调用者本来支持 null 返回，因此只守护此特效查询，不修改通用 Map.GetComponent。
4. **涅瓦莲模块初始化中断**：`NivarianPsionicCap.cs` 不再处理只读取 PsychicAmplifier 的 GivePsylink 调试菜单。VPE 已将唯一 maxSeverity 读取替换成 TotalPoints；旧检查期待一次、实际零次，抛错后后半批兼容注册全部跳过。该菜单从不读取涅瓦莲 attunement Def，因此移除它不会减少涅瓦莲上限同步；实际 attunement 读点保留。

5. **帝国 UI 捐赠同步**：`ImperiumDonation.cs` 将完整捐赠移入同步命令，详见上节。

新增组独立安装、独立失败回滚，类别开关仍生效。未修改电网、全局随机流、全部 JobDriver、全部 Projectile 或 MP 框架本体。未改核心 DLL 与 About 中的核心版本。
